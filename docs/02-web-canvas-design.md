# Web 前端重做方案：自由画布节点图

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.1 · 方案稿（待对齐） |
| 上游依据 | `PRD_v0.1.md` §9 Web 信息架构、`README.md` Web 前端一节、`docs/01-kernel-and-config-model.md` |
| 现状 | `web/` 为浅色三栏列表脚手架，**没有节点依赖图**，与 README 承诺的「节点图」不符 |
| 目标 | 以**自由画布**为核心工作入口，重做 Web 前端；先做对「图 + 交互」，视觉风格后置 |

---

## 0. 这次要解决的核心问题

上一版（及历史几版）无法满足的原因，不是配色不够好看，而是**信息形态错了**：

- 用「列表」表达「图」——节点之间的**依赖 / 交付 / 分解**关系全部丢失，用户看不到「谁依赖谁、谁缺什么」。
- 没有「画布」这个心智——协作图本质上是一张可以自由摆放、随时增删改的**空间图**，而不是一张可滚动表格。
- 状态只是灰字 badge，没有「这个节点在等谁、卡在哪」的即时感知。

因此本方案把「自由画布节点图」设为第一公民，其余（概览 / 连接 / 详情）都围绕它组织。

---

## 1. 设计原则

1. **图为先**：节点 + 关系边是主视觉，列表只是退化视图。
2. **自由画布**：可拖拽节点、平移画布、缩放（滚轮/触控板），像 Figma/Miro 一样随意摆放。
3. **数据驱动**：画布上的每个元素都直接映射后端事实（节点 / 关系 / 产物 / 事件 / 介入项），**不引入第二套状态**。
4. **零依赖、零构建**：延续项目灵魂，用原生 HTML/CSS/JS + SVG，不引入框架与打包器。
5. **先图后风格**：P0 用中性占位视觉把「图与交互」做对，深空/发光/玻璃等风格在 P2 统一上。

---

## 2. 信息架构（整体布局）

```
┌──────────┬───────────────────────────────────────────────┬──────────────┐
│ 左栏      │  顶栏（项目名 · 需求 · 缩放 · 运行示例 · 连接）    │  右侧详情     │
│ 品牌      │                                               │  (选中节点后  │
│ 项目列表   │                                               │   滑出)      │
│ 视图切换   │           无限画布（自由拖拽/缩放）              │  - 有效上下文 │
│ 底部状态   │           节点 + 关系边 + 浮动工具               │  - 操作区    │
└──────────┴───────────────────────────────────────────────┴──────────────┘
```

- **左栏（窄，可折叠）**：品牌、项目列表（切换当前项目 = 切换画布）、底部 LLM/连接状态。
- **顶栏**：当前项目名、所属需求目标、缩放控制（适应 / − / + / 100%）、「连接」入口、「运行示例」。
- **画布（主体）**：无限画布，节点与关系边在此渲染、编辑。
- **右侧详情**：选中节点后侧滑，展示该节点**有效上下文** + 可执行操作（复用现有 `/context/:nodeId`）。
- **浮动工具条（画布内，左下/左上）**：新建节点、连线模式、自动整理、框选。

## 3. 画布核心

### 3.1 节点（Node）

画布节点是一张**紧凑卡片**，承载「这个工作单元此刻是什么状态」：

| 元素 | 内容 | 来源 |
| --- | --- | --- |
| 名称 | 节点 `name` | Node |
| 状态徽章 | `executionStatus` | Node |
| 待处理角标 | 未解决介入项数量（琥珀圆点+数字） | interventions |
| 产物/版本 | 最新产物版本号或「尚无产物」 | artifacts |

节点按 `executionStatus` 呈现**可区分的状态**（P0 先用颜色块+图标，P2 再上发光动效）：

| executionStatus | 视觉语义 |
| --- | --- |
| 待开始 | 中性灰 |
| 处理中 | 强调色（脉冲） |
| 等待人工 | 琥珀（醒目，提示「等谁」） |
| 受阻 / 执行异常 | 红色 |
| 本轮结束 | 绿色（已交付一轮） |
| 暂停 / 已取消 | 弱化灰 |

> 关键点：**「等待人工」必须在画布上一眼可见**——这是产品「人工介入是正常环节」的落地。

### 3.2 边（Relation）

按 `Relation.type` 区分四种边，语义清晰：

| 类型 | 方向语义 | 线型 | 颜色 |
| --- | --- | --- | --- |
| `dependency` 输入依赖 | from → to 表示「to 需要 from 的产物」 | 实线箭头 | 绿色 |
| `delivery` 成果交付 | from → to 表示「from 的成果交给 to」 | 实线箭头 | 紫色 |
| `decomposition` 需求分解 | 需求/父 → 子节点 | 虚线箭头 | 灰色 |
| `grouping` 分组 | 结构化分组，非执行依赖 | 点线（无箭头） | 浅灰 |

- **依赖边可携带「满足状态」**：复用内核 `structuralInputCheck`，上游有产物 → 边为实/亮，上游尚无产物 → 边为虚线/暗 + 缺口标记。这样「缺什么」直接在图上可见。
- 边上显示 `semantic` 小标签（如「需要产品规则」），可开关（避免拥挤）。
- P2 视觉阶段再叠加「能量粒子沿边流动」表达上下文流转。

### 3.3 画布视口

- **平移**：空白处拖拽。
- **缩放**：滚轮/触控板双指，以光标为锚点；顶栏提供 − / + / 适应 / 百分比。
- **无限画布**：可向任意方向延展；背景用点阵网格暗示空间。
- **自动整理（可选）**：即使自由画布，也提供「自动布局」按钮（左→右分层 DAG），作为混乱时的兜底；用户手动拖过的位置优先保留。

## 4. 关键交互清单

| 交互 | 动作 | 结果 |
| --- | --- | --- |
| 选择节点 | 单击节点 | 右侧滑出详情（有效上下文 + 操作） |
| 移动节点 | 拖拽节点 | 更新位置并**持久化** |
| 平移画布 | 拖拽空白 | 平移视口 |
| 缩放 | 滚轮 / 触控板 / 顶栏按钮 | 缩放视口 |
| 新建节点 | 双击空白 / 工具条「+」 | 弹出节点定义表单（P0 仅名称+描述，高级字段后置） |
| 建立关系 | 从节点连接点拖到另一节点 | 选择关系类型 + semantic，生成 Relation |
| 编辑/删除 | 选中后工具条或快捷键 Delete | 删除节点/边（复用现有删除语义） |
| 运行流水线 | 详情面板「运行」 | 调 `/pipeline/run`，刷新节点状态 |
| 提交产物 | 详情面板「提交产物」 | 调 `/artifacts`，边满足状态刷新 |
| 人工介入 | 详情面板「补充/复查/解决」 | 更新介入项，画布状态刷新 |
| 键盘 | Delete / Esc / 双击空白 | 删除 / 取消 / 新建 |

## 5. 视觉方向（P2 实施，本方案只锚定方向）

- 基调候选：**深空深色**（背景深色、状态发光、玻璃拟态面板、能量粒子动效）——README 已承诺的方向。
- 浅色编辑部风作为备选，P1 完成后由你拍板。
- P0 阶段用**中性浅色 + 高可读性 + 清晰的状态色**即可，重点是交互与信息结构正确，不在这轮纠结风格。

## 6. 技术方案

### 6.1 渲染：原生 SVG

- 节点 = SVG `<g>`（含卡片矩形 + 文本 + 状态点），边 = SVG `<path>`（带箭头 marker）。
- 用 SVG 而非 `<canvas>` 的理由：元素可被 CSS 样式化、事件命中天然、文字清晰、缩放平移只需变换 `viewBox`/`transform`，且**零依赖**。
- 平移/缩放 = 维护一个 `{x, y, k}` 视口变换，套在 `<g>` 上；节点世界坐标不变，仅变换视图。

### 6.2 数据来源

现有后端已够用，无需为画布重写接口：

- `/snapshot` → 节点、关系、项目、需求（画布初始数据）。
- `/context/:nodeId` → 节点详情有效上下文。
- `/project/:id/summary` → 宏观看板（若保留概览视图）。
- 写操作复用现有 POST 端点。

### 6.3 需要后端配合的唯一改动：节点位置持久化

自由画布要求「节点摆在哪」在刷新/换浏览器后不丢。当前 `Node` 模型**没有位置字段**，有两个方案：

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| **A（推荐）** | 给 `Node` 增加可选字段 `position?: {x,y}`，并加一个更新位置的端点 | 改动小、最直接；位置作为「节点展示快照」进入模型 |
| B（更纯） | 在 `Store` 单开 `nodePositions: Record<nodeId,{x,y}>`，独立持久化 + 端点 | 领域模型保持纯净，但多一套并行结构 |

> 倾向 **A**：位置是「用户在画布上摆放节点」的事实，属于节点可配置展示属性，不算业务领域污染；实现与持久化（FR12 快照）改动极小。

### 6.4 前端文件结构（保持零构建）

```
web/
├── index.html        # 单页外壳（左栏 + 顶栏 + 画布容器 + 详情抽屉）
├── style.css         # 布局 + P0 中性视觉
├── app.js            # 入口：装配数据、路由视图、事件绑定
├── graph.js          # 画布引擎：SVG 渲染、视口平移缩放、命中检测
├── model.js          # 前端数据模型：从 /snapshot 归一化成图结构
└── api.js            # fetch 封装（现有 api 逻辑抽出）
```

| 阶段 | 范围 | 验收 |
