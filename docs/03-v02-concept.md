## 0. 一句话灵魂

> **一切皆节点；相邻才交易；流即 IO；I 可篡改、O 不可篡改；消息上行归根、根可改写为新输入；产物上行逐级验收、可跳过可打回；上帝只观察、统计与反馈。**

可扩展性测试：新增一种能力（Agent / CI-CD / SKILL）、接入一棵新树、给上帝加一个能力——**都只改变树的结构或节点配置，不改内核**。

---

## 1. 三大对象

| 对象 | 是什么 | 关键规则 |
| --- | --- | --- |
| **节点** | 唯一的结构对象，可抽象为任何能力单元（Agent、CI-CD、代码清理、自动打包……） | ID 全局唯一、可算法生成；只能与**相邻节点**（父 + 子）直接交互 |
| **通知** | 消息机制 | **消息是通知的产物**；沿树逐跳传递，不广播 |
| **SKILL** | Agent 能力的扩展，本质是 MD 文件 | 与节点是**组合关系**：SKILL 作为部件被组合进节点的能力，自身不是节点、不独立流转、不进入树结构 |

> `[解读]` 流经树的「木头 / 椅子 / 剩余木头」是**流数据**（I 输入 / O 输出），不单列为对象——流本身即 IO。

---

## 2. 《源》树规则（静态结构）

1. **以「我」为根**：每个账户的节点树中默认存在「自己」节点，**不可移动、不可删除**。
2. **只能向下建**：只能在自有节点下方创建新节点；开叉分支无数量限制。
3. **多树共存**：一个账户可以存在于**任意多棵树**（多个组织/团队/项目）。
4. **可见性**：自建节点默认**私有**（自己的 Agent 场景）；可选**公有**，向全系统暴露（为组织协作提供能力支持）。`[待决 B]` 子节点是否继承父节点可见性。
5. **相邻交易**：节点只能与父、子直接交互；同树内非相邻节点**不能直接联系**（这就是「像区块链」的点：交易只发生在链上相邻两者之间）。
6. **加入他人节点**：进入系统后可加入上司创建的节点，成为树的一部分；权限天然由树形推导（只能向下建 = 权限边界）。

---

## 3. 《流》IO 过程（动态过程）

- **本质是 IO 流**：输入 I 自上而下（A→B→C→D），输出 O 自下而上（D→C→B→A）。
- **投入与产出**：给节点「木头 + 目标（要椅子）」→ 经一段时间 → 产出「椅子 + 剩余木头」；产出由输入决定。
- **分支不改变不变式**：如 A、B-C、D、E-F-G、H，回流为 H、E-F-G、D、B-C、A；始终自上而下、自下而上。
- **汇合 = 全等汇合**：分支汇合点必须等**全部**分支回流完成才继续。
- **超时/异常 = 上帝的责任**：等不到、超时、卡住，由全局 Agent 监督处理 `[待决 C]` 具体动作形态。
- `[待决 D]` I/O 是否版本化；「剩余木头」是否作为 O 的一部分显式回传。
- `[解读]` 「时间」不单列对象：节点上下交互产生**消息碎片**，由上帝据此统计耗时——时间是派生量，不是输入字段。

### 3.1 目标与验收（根的特权与链的纪律）

- **目标由根节点提出**：「木头→椅子」的期望产出与验收条件挂在根上。
- **验收自下而上逐级进行**：产物沿回流路径向上传递，每经过一个节点，该节点三选一：
  1. **通过**——验收认可，继续向上传；
  2. **跳过**——不参与验收，直接放行 `[待决 H]` 跳过的精确语义；
  3. **打回**——拒绝，把这次自下而上的传递沿路退回下游。
- **任何节点不得篡改产物**：产物的内容在传递途中不可被中间节点修改，只有「放行 / 退回」两种权力，没有「改写」的权力。

> **E + G 的不对称性**（本概念的关键设计，已升格为 §3.2 守恒律）：
> - 消息（上行信息流）：逐跳转发 → **根是唯一监听者，可改写为新 I 向下流转**。
> - 产物（上行成果流）：**不可篡改** → 各级只有 通过 / 跳过 / 打回。
> - 中间节点对 O 没有表达权，只有放行和退回权；对 I 的加工权见 §3.2。

### 3.2 流的守恒律：I 可篡改、O 不可篡改

- **I（输入，自上而下）可篡改**：每一级节点都是自己子树的根——向下传递输入时，可基于自己的理解加工、改写后再交给子节点；根把上行消息改写为新 I，是这条法则在消息层的体现。
- **O（产物，自下而上）不可篡改**：产物一旦产出，向上传递途中任何节点不得修改，只能 通过 / 跳过 / 打回。
- **改自己的产物 = 新版本**：修改已产出的产物 = 产出**新的 O 版本**，旧 O 留在链上不可篡改——追加式账本，与区块链同构。

## 4. 《听》消息机制 + 上帝

### 4.1 消息

- 消息是**通知的产物**；节点上下交互、流运转时产生（即「消息碎片」，一笔带时间戳的相邻交易记录，串链可追溯）。
- **路由**：消息逐跳向上汇聚到**根节点**；根是全树**唯一的监听者**。
- **根的改写权**：根可以根据自己的理解把收到的消息**篡改/改写为新的 I**，再自上而下流转——但这是根**主动**的行为；**根不动作，消息到此为止，不向下传递**（不广播）。这是 §3.2「I 可篡改」法则在消息层的体现。

### 4.2 上帝（全局 Agent）—— 苍天与皇帝

**根 = 皇帝（天子），上帝 = 苍天。** 二者的关系：

- **苍天在上，苍天有眼**：上帝俯视整棵树，一切消息碎片都留痕于它——全局账本、时间统计、链上可追溯的来源。
- **苍天不言，只降天象**：上帝不直接动作、不干预树；超时、异常、卡住、进度 = 「天象示警」，通过消息反馈给皇帝。
- **天子执政**：根是唯一的决策位——解读天意（上帝的反馈），主动改写消息为新 I 向下流转，或让消息止步于此。
- **天命即监督**：上帝不替根做主，但根的一举一动都在苍天眼里。
- **能力即节点**：上帝扩展能力 = 给它下挂节点（天界亦有其机构），统一不变。

| 职责 | 说明 |
| --- | --- |
| 观察 | 监听全树的消息碎片，观察《流》的运转（全局账本） |
| 监督 | 汇合等待、超时、异常——天象示警 |
| 反馈 | 把汇总分析反馈给根节点（天子解读天意后决策），呈现在全局看板，人可提前干预 |
| 统计 | 把消息碎片聚合为**时间统计**（谁花了多久、卡在哪） |
| 扩展 | 上帝**本身是节点**：它的「下个节点」（下游分支）决定它拥有什么能力——想给上帝加能力，就是给它建子节点 |

> `[待决 F]` 结构位置：上帝是根之上的**父节点**（「天子」——根是苍天的子，二者相邻，反馈走父子通道；一个苍天照看所有树）？还是树外的旁听位？我的倾向：**上帝是根的直接父节点**。

---

## 5. 《动》actions（节点的延伸能力）

- **Agent Models**：节点配置的 Agent 能力，与传统 AI 一致，可「当作人」。
- **SKILL**：Agent 的伴生能力（MD 文件），与节点为**组合关系**（§1）。
- **CI-CD**：提交代码 → review → 代码检查 → 代码清理 → 打包发布二维码等；**保持抽象**，作为节点扩展能力存在，具体外部链接形式后定。
- **……**：能力类型开放，新增能力 = 新增节点类型配置，不改内核。

## 8. 落地顺序建议（最小闭环）

1. **树内核**：节点（父子唯一关系）+ 多树 + 只能向下建 + 私有/公有。
2. **流**：I 自上而下、O 自下而上、全等汇合、相邻交易消息碎片。
3. **听**：消息上行归根 + 根改写为新 I + 上帝（观察/监督/反馈/时间统计）。
4. **动**：节点配置 Agent / SKILL 组合 / 抽象 CI-CD 动作。
5. **验收**：根提目标 + 逐级 通过/跳过/打回 + 产物不可篡改。
6. **前端**：现有画布改造成「我的子树视图 + 多树切换 + 消息流动画」。

> 原则：每一步都保持「内核极简、一切皆配置、能力皆节点」；遗留项（B/C/D/F/H）先按「我的倾向」实现，随时可改配置而非改内核。
