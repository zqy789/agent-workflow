## 0. 一句话世界观

> **栽下梧桐树，引得凤凰来。**
> 一个《源》是一粒种子；种子落地生根，长成一棵梧桐——树干是根节点（组织本身，即「我」），枝桠是从根向下构建的组织结构，树液是《流》，花苞新叶果实是《动》，风与天光是《听》，年轮是账本。

---

## 1. 核心思想：一棵树，两个视角

梧桐树不是装饰，而是**组织结构的投影**。同一份数据（`GET /trees/:rootId`）有两个视角：

```
宏观视角（梧桐树首页）  ←──── 同一份数据 ────→  微观视角（节点房间 · 数据终端）
看整棵树的形态与生命              钻进一个节点看它的表格与操作
```

- 首页 = 你的梧桐树：**树不是画出来的，是长出来的**——结构长什么样，树就长什么样。
- 点任意枝 / 叶 / 果 → 进入该节点的房间（v6 数据终端，作为「近看」）。
- 房间操作（验收 / 运行 / 剪枝 / 挂载能力）→ 返回树时树已变化（果实成熟、新枝抽出、枯枝剪断）。
- 多树 = 梧桐林（左栏切换，每棵按自身结构生成）。

## 2. 世界观映射：四个模块，各自在树上活着

| 模块 | 树的化身 | 具体表现 |
| --- | --- | --- |
| **《源》** | 种子 → 树干 → 树冠 | 创建源 = 种下种子；树干 = 根节点（顶级节点，组织本身 /「我」）；枝的分叉 = 层级结构——**形状就是源** |
| **《流》** | 树液 | I 输送 = 树液从树干上输到枝叶（蓝，上行）；O 回流 = 果实养分从枝叶回流到树干（绿，下行）；卡住的枝 = 树液断流 |
| **《动》** | 枝叶的生命活动 | 花苞 = 还没动（等待）→ 新叶舒展 = 正在动（运行）→ 果实 = 动完了（完成）→ 果实落地 = 打回重来；节点挂载的 Agent / SKILL / CI-CD = 这根枝「用什么方式动」 |
| **《听》** | 风与光 | 全局 Agent = 天光（照见一切、只观察不干预）；消息 = 沿枝传播的风——提醒拂过某枝时泛红摆动；待办 = 红果 |
| 账本 | 年轮 | 时间与事实一圈圈积累在根基，追加式不可篡改（圈数随碎片数增长） |
| 公有 / 共享 | 凤凰 | 公有或被外部引用的枝头栖凤——「源」对外共享的姿态 |

### 2.1 「区分性」的解法：视觉通道分离

树要同时显示组织、状态、流、听，且一眼可分。原则：**每个模块独占一种感官通道**：

| 模块 | 独占通道 |
| --- | --- |
| 源（结构） | 形状（枝的拓扑） |
| 流 | 运动（树液流动） |
| 动 | 颜色 + 形态（花苞 / 新叶 / 果实） |
| 听 | 瞬时事件（风的涟漪、红果、天光——出现即消失，不常驻） |

**克制铁律**：静态时树只讲「源 + 动」；流与标签在 hover 或显式开关时才点亮。想看的层，点亮哪层。

## 3. 生成规则（结构 → 树形）

| 结构事实 | 树上的表现 |
| --- | --- |
| 深度 | 主干 → 主枝 → 侧枝 → 细枝，逐级变细 |
| 子节点数量 | 分叉数量；子树越大，该枝越粗壮（对数尺度） |
| 节点状态（三态） | 等待 = 花苞（琥珀含苞）/ 运行 = 新叶（青色脉动）/ 完成 = 果实（绿色，带版本号） |
| 产物版本数 | 果实大小（版本越多果实越饱满） |
| 待办数 | 节点旁的红果计数 |
| 超时 / 卡住 | 花苞枯黄 + 提醒标记（天光扫过该枝） |
| 打回 | 果实落地（该枝进入新一轮孕育） |
| 剪枝 | 枝条断裂痕迹（该枝变枯、渐隐） |
| join 加入上司 | 嫁接痕（另一棵树的枝条接入处） |
| 公有 / 被引用 | 枝头栖凤 |
| 账本 | 树干基部的年轮 |
| I / O 流 | 树液双线：蓝上行（I 输送）/ 绿下行（O 回流） |
| 新建节点 | 虚线新枝 + 「＋」 |
| 全局 Agent | 天光（只照见、不干预） |
| 多源 | 梧桐林（每棵按自身结构生成） |

## 4. 视图体系

1. **首页 · 梧桐树**（全局）：左侧梧桐林、中央树、右侧小读数面板（等待/运行/完成/提醒 + 最新碎片）；
2. **节点房间 · 数据终端**（v6 表格：仪表行 / 回流产物·待验收表 / 能力表 / 产物版本链 / 相邻消息）——「← 梧桐树」返回；
3. **全局 Agent 监控条**（底部常驻，两视图共有：时间统计 / 提醒 / 碎片流）。

视觉基调：深黑 · 白字 · 发丝分割线 · 等宽数字（OKX 式克制）；树本身为几何抽象风格（细线 + 光点，与数据终端一致）。

## 5. 难度拆解与分阶段里程碑

### 5.1 四个真问题

| 编号 | 问题 | 思路 |
| --- | --- | --- |
| D1 | 布局：任何结构都长成好看的树 | 深度定高度、叶序定横向、枝粗随子树规模对数增长、主干始终一根；先规则层验证（两种结构 → 两棵树） |
| D2 | 区分性：组织 / 状态 / 流 / 听同屏可分 | §2.1 视觉通道分离 + 克制铁律 |
| D3 | 交互：点击枝果进房间、返回见变化 | 命中热区 + hover 浮层 + 状态回写（后端状态本就驱动一切，规则不变） |
| D4 | 真实渲染与规模 | 同一套规则：脚本验证形状 → JS 渲染接 `GET /trees/:rootId`；节点多时远端枝折叠成「一团叶」 |

### 5.2 里程碑（每阶段独立可验收）

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| P1 种子发芽 | 结构 → 树形（布局 + 枝干） | 两种不同结构长出两棵明显不同的树，不打架 |
| P2 生命阶段 | 三态末梢形态 + 标签 | 花苞 / 新叶 / 果实一眼可辨 |
| P3 树液 | I/O 双线流动 | 流的方向与语义一致，hover 才点亮 |
| P4 风与光 | 天光 + 提醒涟漪 + 红果 | 「听」瞬时可见、不常驻 |
| P5 点进去 | 点击节点进房间，返回见变化 | 树上验收 → 果实成熟；剪枝 → 枯枝 |
| P6 梧桐林 | 多源、嫁接痕、生长动画、性能 | 完整梧桐林 |
